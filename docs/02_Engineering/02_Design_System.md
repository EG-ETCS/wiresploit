# Design system

For coding agents and developers building any Wiresploit interface: the web
application, reports, docs pages or CLI output. **Read this before writing UI
code.** Where a library default disagrees with this page, this page wins.

!!! note "Brand kit assets are not in this repo"
    This page references files from the Wiresploit brand kit: `tokens/colors.css`,
    `tokens/tokens.json` (generated by `source/build.py`), the fonts in `fonts/`,
    the logos in `logo/` and the patterns in `patterns/`. Those assets live in the
    brand kit, not in this repo. Paths on this page are relative to the brand kit
    root. When an app needs them, copy `tokens/`, `fonts/` and `logo/` into that
    app and fix the paths.

    - Canonical values live in the token files. The tables below copy them; if
      they ever differ, the token files are right.
    - The human-facing version of these rules is `Wiresploit-Brand-Manual.pdf`
      and `brand-guidelines.html`, also in the brand kit.

!!! note "Terminology"
    Sections 5 and 8 use the BRD's role names (Capture Node, Snapshot Node,
    Injection Node). For component names in code and docs, the terminology table in the
    [coding rules, §1.5](01_Coding_Rules.md#15-terminology) applies: a Node has
    Capture and Actions functions.

## 1. The short version

Wiresploit puts a device's network traffic and onboard buses (UART, SPI, I2C, wireless) on one timeline for security analysts. The interface should feel like a precise lab instrument that is pleasant to use: light, open, plain. Its output can end up as evidence in a report, so it must never look or sound like it overclaims.

**Always**

- Light theme by default: white background, ink text, grey lines.
- Use the semantic tokens (`--ws-bg`, `--ws-text`, `--ws-line`, …), not raw hex values.
- Use lane colours **only** for protocol data: timeline blocks, protocol badges, legend swatches, charts of bus data.
- Keep lanes in the fixed order and colour each by its protocol, never by position.
- Label every lane and every flag with text. Colour is never the only signal.
- Use JetBrains Mono for anything a machine produced: hex, IDs, timestamps, addresses, payloads.
- Self-host fonts and assets. The product must run air-gapped, so no runtime CDN calls.
- Write UI text in sentence case, plain and exact, with units.

**Never**

- Lane colours on text, buttons, navigation, headers or backgrounds.
- Signal red for decoration. It means "this matters": the main action, a flagged finding or an active injection.
- More than one primary (red) button in a view.
- Gradients, glows, neon, glassmorphism, scanlines, glitch effects, Matrix green, skulls, hoodies or padlock clichés.
- Text inside timeline blocks (contrast varies by lane). Put it in tooltips, the details panel or beside the block.
- Re-drawing or animating the logo in code. Use the SVG files.
- Hype words in copy: "pwn", "hack anything", "military-grade", "AI-powered", "next-gen", exclamation marks.

## 2. Colour

### Semantic tokens (use these)

| Token | Light | Dark (`.ws-dark`) | Use |
|---|---|---|---|
| `--ws-bg` | `#FFFFFF` | `#121416` | Page and app background |
| `--ws-panel` | `#F3F4F5` | `#1A1D20` | Side panels, table hover, code blocks, selected column |
| `--ws-line` | `#E3E5E8` | `#2A2E33` | Borders, dividers, table rules, ruler ticks |
| `--ws-text` | `#121416` | `#F3F4F5` | Headings, body text, icons |
| `--ws-text-muted` | `#5F6670` | `#A9AFB6` | Secondary text, labels, captions |
| `--ws-text-subtle` | `#8A9099` | `#8A9099` | Placeholders, ruler numbers, metadata. On light: 18 px+ or non-essential only (3.2:1) |
| `--ws-signal` | `#D63A25` | `#F2614C` | Primary button, flagged findings, active injection |
| `--ws-on-signal` | `#FFFFFF` | `#121416` | Text and icons on `--ws-signal` |
| `--ws-wire` | `#D3D6DA` | `#474C52` | The 2 px wire line in each timeline lane |

Derived states (not tokens; use these exact values):

- Primary hover: light `#BC321F`, dark `#F47766`.
- Flag tint (background behind a matched secret): `--ws-signal` at 12% opacity.
- Popover / menu shadow: `0 8px 24px -8px rgba(18, 20, 22, .25), 0 1px 2px rgba(18, 20, 22, .06)`. Nothing else gets a shadow.

### Lane colours (data only)

The order is fixed and was validated for colour-blind separation between neighbouring lanes. Show only the lanes a session uses, but keep this order and each protocol's own colour. Hiding UART does **not** shift SPI's colour.

| # | Lane | Token | Light | Dark |
|---|---|---|---|---|
| 1 | Network (HTTP, TCP, MQTT…) | `--ws-lane-network` | `#2A78D6` | `#3987E5` |
| 2 | UART | `--ws-lane-uart` | `#C98500` | `#C98500` |
| 3 | SPI | `--ws-lane-spi` | `#199E70` | `#199E70` |
| 4 | I2C | `--ws-lane-i2c` | `#6250D6` | `#9085E9` |
| 5 | Wireless (BLE, LoRa, RFID…) | `--ws-lane-wireless` | `#D55181` | `#D55181` |
| 6 | Snapshot | `--ws-lane-snapshot` | `#8A9099` | `#A9AFB6` |

GPIO and other logic-level signals are levels, not traffic, so they get no hue. Draw them as a 1.5 px square-wave line in `--ws-text-muted` on their own lane, placed after I2C. For any other new protocol, ask before adding a colour. **Do not invent a seventh hue.** Raw greys (`--ws-grey-100` … `--ws-grey-700`) exist for illustrations; UI code uses the semantic tokens.

## 3. Typography

| Font | Use | Files |
|---|---|---|
| **Inter Tight** | Headings, big numbers | `fonts/InterTight-var.ttf` (variable, 100–900) |

|---|---|---|---|---|
| Display (docs, marketing only) | Inter Tight | 56 / 58 | 800 | −0.035em |
| H1 | Inter Tight | 32 / 36 | 800 | −0.025em |
| H2 | Inter Tight | 24 / 30 | 700 | −0.02em |
| H3 | Inter Tight | 18 / 24 | 700 | −0.01em |
| Body (app) | Inter | 14 / 20 | 400 | 0 |

## 4. Layout, shape and motion

- **Spacing scale (px):** 4, 8, 12, 16, 24, 32, 48, 64, 96. Use nothing in between.
- **Radii:** 4 px for timeline blocks and small chips, 6 px for buttons and inputs, 10 px for cards and panels, 999 px for pills.
- **Borders:** 1 px `--ws-line`. Prefer a border or `--ws-panel` fill over shadows.
- **App shell:** 56 px top bar with the logo at 20 px tall on the left; 240 px left sidebar (collapsible); 24 px content padding. The timeline always gets the full remaining width.
- **Docs and prose:** 1120 px max container, 720 px max line length.
- **Breakpoints:** 640, 1024, 1440. Below 640 px, use a 16 px side gutter and no horizontal page scroll; the timeline scrolls inside its own frame.
- **Motion:** 150 ms ease-out for hover and press, 200 ms for panels and popovers. No bounce or spring. Live timeline scrolling is linear. Respect `prefers-reduced-motion` by removing non-essential motion.
- **Icons:** Lucide (MIT) or an equivalent outline set, 16 or 20 px, 1.5–1.75 px stroke, `currentColor`. No filled or duotone sets.

## 5. Components

### Buttons
| Variant | Style | When |
|---|---|---|
| Primary | `--ws-signal` fill, `--ws-on-signal` text, 600 weight, 36 px tall, 0 16 px padding, 6 px radius | The one main action in a view: Start capture, Export report, the confirm step of an active action |
| Secondary | Transparent, 1 px `--ws-line` border, `--ws-text`; hover fill `--ws-panel` | Everything else |
| Ghost | Text only, `--ws-text-muted`; hover `--ws-text` | Toolbars, tertiary actions |

- Disabled: 40% opacity, `cursor: not-allowed`, no hover change.
- Focus (all interactive elements): `outline: 2px solid var(--ws-text); outline-offset: 2px;` on `:focus-visible`.
- Labels are verbs that say exactly what happens: "Send 12 UART frames", not "Go" or "Submit".

### Active actions (injection, fuzzing, replay, reset, power-cycle)
These change the device under test, so they **always** need an explicit confirmation step. That's a product requirement, not just a style choice.
- The trigger is a secondary button. It opens a dialog that states the target, the action and the count: "Send 12 forged I2C writes to 0x50 on CN-02?"
- The dialog's confirm button is primary (signal red) and repeats the verb. Cancel is secondary and takes initial focus.
- While running, show an "Active" chip (signal-red dot plus text) in the top bar until the action ends.

### Inputs
36 px tall, 1 px `--ws-line` border, 6 px radius, `--ws-bg` fill, 14 px text, `--ws-text-subtle` placeholder. On focus: border `--ws-text`. On error: border `--ws-signal`, plus a 12 px message below in `--ws-signal` that says what's wrong and how to fix it.

### Cards and panels
Either `--ws-bg` with a 1 px `--ws-line` border and 10 px radius, or a `--ws-panel` fill with no border. 16 px padding (compact) or 24 px (default). No shadows.

### Badges and chips
- **Protocol badge:** an 8 × 8 px square in the lane colour, then the protocol name in `--ws-text`, 12 px / 500. 22 px tall, 6 px radius, 1 px `--ws-line` border. The colour is on the square only, never on the text.
- **Status chip:** neutral (`--ws-panel` fill, `--ws-text-muted` text) with an icon. "Flagged" and "Active" use a `--ws-signal` dot plus text.

### Tables
- Header: Inter 12 / 600, `--ws-text-muted`, sentence case, bottom border `--ws-line`.
- Rows 40 px tall (32 px compact), 1 px `--ws-line` dividers, `--ws-panel` on hover, no zebra stripes.
- Hex, IDs, timestamps and addresses in mono. Numbers right-aligned with tabular figures.

### Hex and payload views
Mono 13 / 20. Offset column in `--ws-text-subtle`, bytes grouped in pairs, ASCII column on the right. A matched secret gets a 12% `--ws-signal` background and a 1 px underline in `--ws-signal`, plus a "Secret" label in the gutter.

### Empty, loading and error states
- **Empty:** one plain sentence and at most one action, for example "No Capture Nodes connected. Plug one in, or add one by IP." No illustrations.
- **Loading:** a skeleton in `--ws-panel`, or a 2 px indeterminate bar in `--ws-text`. Never a spinning logo.
- **Error:** say what happened, then what to do. "Capture Node CN-02 stopped responding. Check its cable, then select Reconnect."
- **Toasts:** `--ws-text` fill with `--ws-bg` text, bottom-left, 4 s (errors stay until dismissed).

## 6. The timeline (core component)

The timeline is the product. Get these details exactly right.

```
 ┌──────────────┬───────────────────────────────────────────────────────────┐
 │              │ +0 ms        +2 ms         ┌CB-0142┐       +6 ms           │  ruler 28 px
 ├──────────────┼────────────────────────────┼───────┼──────────────────────┤
 │ ■ Network    │ ───████────────██──────────│███████│────────████──────────│  lane 32 px
 │ ■ UART       │ ──────────███──────────────│ █████ │──────────────█████───│
 │ ■ SPI        │ ───██─██───────────────────│ ███ █ │───────███────────────│
 │ ■ I2C        │ ───────────────────██──────│ ████  │───────────────────██─│
 │ ■ Snapshot   │ ───────────────────────────│   ◆   │──────────────────────│
 └──────────────┴────────────────────────────┴───────┴──────────────────────┘
   label 160 px                                selected Communication Block
```

- **Lane:** 32 px row (24 px compact). A 2 px `--ws-wire` line runs the full width through the centre of the row.
- **Label column:** 160 px, sticky on horizontal scroll. Contents: an 8 × 8 lane-colour square, the protocol name in Inter 13 / 500, and the node ID (`CN-02`) in mono 11, `--ws-text-subtle`.
- **Blocks:** 18 px tall (14 px compact), 4 px radius, filled with the lane colour, vertically centred on the wire. Minimum width 3 px. Zero-duration events are 3 px ticks. Leave a 1 px `--ws-bg` gap between adjacent blocks so they never merge.
- **No text inside blocks.** Hover shows a tooltip (mono 12) with protocol, timestamp, duration and a decoded summary. Click opens the details panel.
- **Hover:** a 1 px `--ws-text` outline on the block.
- **Communication Block (selected):** a column across all lanes spanning the CB's time range: `--ws-panel` fill behind the blocks, 1.5 px `--ws-text` outline, 6 px radius. Above it in the ruler, a pill with the CB ID (`CB-0142`) in mono 11 / 600, `--ws-bg` text on `--ws-text` fill.
- **Flagged (secret found):** the block or CB outline turns `--ws-signal` and gets a 6 px `--ws-signal` dot. The details panel names the finding in plain text.
- **Injected traffic** (sent by Wiresploit, not observed): keeps its lane colour, with a 1.5 px `--ws-signal` outline and an "Injected" label in the tooltip and details panel. Observed and injected traffic must never look identical.
- **Snapshot Block:** a 12 px diamond in `--ws-lane-snapshot` on the Snapshot lane, with its short description in Inter 12, `--ws-text-muted`, beside it ("LED on").
- **Ruler:** 28 px tall, mono 11 `--ws-text-subtle` labels, `--ws-line` ticks. Offsets look like `+4.1 ms`; absolute times are ISO 8601 UTC with microseconds (`2026-10-22 01:42:07.123456 UTC`).
- **Cursor:** a 1 px `--ws-text` vertical line with a mono 11 readout.
- **Timing honesty:** wherever a time or a correlation is shown, show its confidence too (`±40 µs`). Never round it away.
- **Keyboard:** ← → move the cursor between events, ↑ ↓ change lane, Enter opens details, Esc clears the selection. Every block has an `aria-label` such as "UART, +4.1 ms, 9 bytes".

## 8. Writing in the UI

- Sentence case, no exclamation marks, no "Oops", no jokes in errors.
- Be exact and include units: `12 events`, `+4.1 ms`, `±40 µs`, `9 bytes`.
- Capitalise product terms, and spell out abbreviations the first time on a screen: **Capture Node**, **Snapshot Node**, **Injection Node**, **Core**, **Communication Block (CB)**, **Snapshot Block (SB)**, **Device Under Test (DUT)**.
- Report what was observed, not what it means. Write "Plaintext password seen on UART at +4.1 ms", not "Password leak!".
- Name the consequence of active actions before they happen.

| Write | Not |
|---|---|
| See every layer at once. | Pwn any IoT device in seconds!! |
| Timing confidence: ±40 µs | Perfectly accurate timing |
| Plaintext password seen on UART at +4.1 ms | CRITICAL!!! Password leak detected!!! |
| Send 12 UART frames to the DUT? | Are you sure? |
| No sessions yet. Start a capture to record one. | Nothing to see here 🙂 |

## 9. Accessibility

- WCAG 2.2 AA. Body text at least 4.5:1, large text and UI parts at least 3:1. The semantic text tokens already meet this on `--ws-bg` and `--ws-panel`, except `--ws-text-subtle` on light (3.2:1, large or non-essential text only).
- Never use colour alone: lanes have names, flags have text, active state has a label.
- Every interactive element is reachable by keyboard and has a visible `:focus-visible` outline.
- Hit targets at least 24 × 24 px. Timeline blocks narrower than that get a larger invisible hit area.
- Support `prefers-reduced-motion` and `prefers-color-scheme`. The default is light, with a manual toggle that adds `.ws-dark` to `<html>`.

## 11. Before you finish UI work

- [ ] Only semantic tokens and lane tokens are used, with no stray hex values.
- [ ] Lane colours appear only on data, and follow the protocol, not the position.
- [ ] At most one signal-red primary button per view. Red elsewhere means flagged or active.
- [ ] Every lane, flag and status has a text label.
- [ ] Hex, IDs and timestamps are in JetBrains Mono, numbers have units, and times show their confidence.
- [ ] Active actions have a confirmation dialog that names the target and count.
- [ ] Copy is sentence case, plain and exact, with no hype or exclamation marks.
- [ ] Keyboard focus is visible, and contrast passes in both light and dark.
- [ ] Fonts and assets load locally, with no external requests at runtime.
- [ ] Checked at 375 px, 1024 px and 1440 px widths.
